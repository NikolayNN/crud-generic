# crud-generic — заметки для агентов

Библиотека CRUD-абстракций для Spring Boot. Публикуется в GitHub Packages как
`by.nhorushko:crud-abstract-generic`. Потребители: LocatorServer, bi-dvr.

## Команды

- Сборка и тесты: `./mvnw -B verify` (или `mise exec -- mvn -B verify`)
- Только библиотека: `./mvnw -B -pl library test`
- JDK и Maven — из mise (`mise.toml`), системного `mvn` на PATH нет.

## Структура

- `library/` — публикуемый артефакт `crud-abstract-generic`
- `test-application/` — демо-приложение, **не публикуется**; несёт 41 интеграционный
  тест (`*IT`), которые гоняет failsafe
- Версия живёт **только** в корневом `pom.xml`, модули наследуют её через `<parent>`

## Чего не делать

- Не публиковать: `mvn deploy` выполняет CI на push в master (хук блокирует).
- Не возвращать неявный маппинг: маппинг только явный, через `MapperRegistry`; никакого
  ModelMapper и рефлексии в маппинге.
- Не ставить теги руками: `v<версия>` создаёт тот же workflow. Тег — выход, а не вход.
- Не поднимать версию перед релизом: версия в pom — та, что разрабатывается.
  Бамп делает `/aurora-release` после релиза.
- Пакет `by.nhorushko.filterspecification` переехал сюда из отдельной библиотеки;
  переименовывать его нельзя — на него завязаны 57 файлов в LocatorServer и bi-dvr.

## Хук `.claude/hooks/guard-bash.sh`

- Хук проверяет весь JSON вызова Bash целиком, а не только `.tool_input.command` — но это
  измеримо верно только для тега. Если слово «tag» (в сочетании с `git`) попадёт в JSON по
  любой причине, например в описании команды, вызов заблокируется, даже если сама команда
  безобидна. Для публикации это не так: слово «deploy» в описании безобидной команды
  проверку не блокирует (exit 0) — регулярка требует `mvn`/`mvnw` рядом с `deploy` без
  кавычки между ними, а не просто слово где-то в JSON, и в описании такого соседства обычно
  нет. Не считайте, что «deploy» ведёт себя так же, как «tag».
- Это же значит, что инлайн-команда вида `echo '...git tag...' | bash .claude/hooks/guard-bash.sh`
  блокирует сама себя. Чтобы протестировать хук или прогнать похожую строку, положите команду
  в файл-скрипт и запустите `bash <путь>` — сам вызов `bash <путь>` этих слов не содержит и
  проходит.
- Тот же хук отказывает и безобидному чтению: `git tag` без аргументов или `git tag -l`
  (просто перечислить существующие теги) матчится той же регуляркой, что и создание тега, и
  блокируется. Это известное и принятое ограничение, а не баг. Обходной путь тот же — команда
  в файл-скрипт, запуск через `bash <путь>`.

Полный стандарт релизов — раздел «Docker image & release flow» в `~/.claude/CLAUDE.md`.
